# R1 机械臂 — 系统架构方案

> 从对话历史提炼 · 2026-06-29

---

## 一、通信架构决策

### 原始场景

上位机 (PC/ROS2) 需要与以下节点通信：
- RS00 电机 ×2（关节1肩、关节2肘）— CAN 扩展帧29-bit
- STM32F103 #1（底盘直流电机 + MT6701）— 需要CAN
- STM32F103 #2（关节3腕旋转 + MT6701 + 夹爪舵机）— 需要CAN
- 舵机夹爪 ×2 — PWM 信号

### 方案对比

#### 方案 A：星型（各节点独立串口到 PC）

```
PC ←UART→ STM32#1 (底盘)
PC ←UART→ STM32#2 (腕旋转)
PC ←CAN→ RS00 (关节1/2)
PC ←PWM→ 舵机夹爪
```

| 问题 | 风险 |
|:-----|:------|
| PC需要多个USB口 | 硬件复杂度高 |
| 多串口时序对齐难 | 分布式时钟无统一时间戳 |
| 串口无硬件CRC | 误码不可检测 |
| 线缆多 | 可靠性下降 |

#### 方案 B：统一 CAN 总线（决定采用）

```
PC ── USB-CANable2 ── CAN bus ── RS00#1
                                ── RS00#2
                                ── STM32#1 (底盘)
                                ── STM32#2 (腕+夹爪)
```

| 优势 | 说明 |
|:-----|:------|
| 同步 | CAN广播，一帧所有节点同时收到 |
| 线缆 | 一条双绞线贯穿全系统 |
| 实时性 | CAN确定性总线，1Mbps下8字节帧≈130μs |
| RS00集成 | 原生CAN，零适配 |
| 可扩展 | 加节点直接挂总线 |

### 核心结论

**统一 CAN 总线优于多路串口**，这也是最终架构的基础。标准帧(11-bit)和扩展帧(29-bit)在同一条总线上完全不冲突，RS00私有协议和STM32底盘协议可以共存。

## 二、节点角色定义

### 网关/主控（5_ChassisController_t1 → 改造后）

```
输入:
  CAN bus (MCLM状态帧 50ms)
  I2C (MPU6050+AK09911 9轴IMU)
  SPI (MT6701 转向角, 可选)

处理 (RTOS 10ms 确定步长):
  ├── IMU 姿态解算 (Mahony AHRS)
  ├── 运动学正解 (电机速度 → 车体 vx/vy/omega)
  ├── 传感器融合 (IMU+轮速里程计)
  ├── 安全监控 (堵转/失联/急停)
  └── 事件检测与上报

输出:
  ├── CAN 0x4A0 融合帧 (10ms/100Hz, 车体速度+时间戳)
  ├── CAN 0x4A1 IMU姿态帧 (10ms/100Hz, 四元数)
  ├── CAN 事件帧 (异常触发)
  └── CAN 急停帧 (最高优先级)
```

### N100/RasPi5 (ROS2 上位机)

```
输入:
  CAN#1 低速通道 (原始状态帧 50ms, 交叉验证)
  CAN#2 高速通道 (网关融合帧 100Hz, 控制主输入)

处理 (Linux, 非实时, ~50ms级):
  ├── 轨迹规划与任务编排
  ├── 运动学逆解 (末端坐标 → 关节角度)
  ├── 状态监控与日志
  ├── 双通道数据交叉验证
  └── 降级策略 (网关超时→用原始数据)

输出:
  ├── CAN 0x125/0x126 底盘速度指令
  ├── CAN 0x130 关节角度指令
  └── CAN 0x101 急停
```

### 电机控制器层（实时 RTOS）

```
3_MCLM_t2 (底盘):
  输入: CAN速度指令 → PID闭环(100Hz) → PWM → TB6612 → DC电机
  输出: CAN 0x325/0x326 状态帧(50ms, 含速度/里程/PWM/flags)

RS00 #1/#2 (肩/肘):
  输入: CAN扩展帧(Type 1/3/4) → 内部位置/电流环
  输出: CAN扩展帧(Type 2 反馈)

3_SteeringArm_t1 (腕+夹爪):
  输入: CAN 0x130/0x430 → 舵机PWM/DC电机
  输出: CAN 0x330 状态帧(50ms)
```

## 三、RS00 电机负载校核

### 电机规格（来自产品 PDF）

| 参数 | 值 |
|:-----|:----|
| 额定扭矩 | **5 N.m** |
| 峰值扭矩 | **14 N.m** |
| 减速比 | 10:1 |
| 空载转速 | 315 rpm (输出轴) |
| 额定转速 | 100 rpm |
| 重量 | 310g |
| 供电 | 48 VDC |

### 1m PVC 杆负载估算（杆重 200-300g）

| 姿态 | 关节2(肘)力矩 | 关节3(腕)力矩 |
|:-----|:-------------|:-------------|
| 竖直(杆朝下) | ~0 Nm | ~0 Nm |
| 水平(杆前伸) | **1.225 Nm** | ~0.25 Nm |
| 水平加速摆动 | +0.08 Nm | — |

RS00 额定 5 Nm，安全系数 > 3，充足。

### 舵机夹爪夹持力

35 kg.cm × 2，夹爪臂长约 2-3cm → 单只夹持力约 137N (14kgf)，抓 200-300g PVC 管绰绰有余。

## 五、关键决策记录

| # | 决策 | 选项 | 结论 |
|:-:|:-----|:-----|:-----|
| 1 | 通信架构 | 多路串口 / 统一CAN | **统一CAN总线** |
| 2 | CAN物理总线数 | 单总线逻辑分路 / 双物理总线 | **单总线分路** (F103单CAN够用) |
| 3 | 网关通信方式 | UART / CAN | **CAN** (兼做融合帧发布) |
| 4 | 融合帧格式 | 拆两帧 / 压缩到一帧 | **拆 0x4A0+0x4A1** |
| 5 | 夹爪控制归属 | STM32#2 / 独立Arduino | **STM32#2** (省一块板) |
| 6 | RS00 CAN发送方式 | subprocess / socketCAN | **socketCAN** (ROS2集成前置) |
